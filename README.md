# Doraemon

`이런 서비스가 있었으면 좋겠다`는 요구사항을 LLM과 구체화하고,  
승인한 계획을 바탕으로 로컬에서 실행 가능한 프로젝트를 생성하고 개선하는 서비스.

## 프로젝트 개요

AI가 프로젝트 전체 구조를 확인하고 파일 수정, 테스트, 오류 해결까지 수행하는  
에이전틱 코딩 방식을 경험하기 위해 시작한 프로젝트

사용자가 만들고 싶은 서비스를 설명하면 요구사항과 구현 계획을 정리하고,  
계획 승인 후 백엔드와 프론트엔드 코드를 생성하여 로컬에서 관리할 수 있도록 구성함.

## 개발 진행 방식

- 에이전틱 AI를 활용한 구현
  구현할 기능과 수정 방향을 제시하고, Codex가 저장소 구조 확인, 코드 작성, 테스트 및 오류 수정을 수행  
  생성된 결과는 직접 확인하면서 구조와 동작을 파악하고 필요한 부분을 다시 수정

- 생성 결과 검토를 통한 학습

  AI가 프로젝트 전체를 확인하고 수정해 주기 때문에 기능 개선 속도는 빨랐지만,  
  변경된 구조를 직접 확인하기 전까지는 프로젝트를 충분히 이해하지 못하는 문제가 있음

  이를 보완하기 위해 백엔드 계층 구조, FastAPI 의존성 주입, 테스트 코드, CI와 Docker 설정 등을  
  하나씩 확인하고 정리하는 방식으로 진행

## 주요 기능

- 사용자 요구사항을 정리하며 구현계획 생성 
- 구현 계획의 사용자 승인시 프론트·백 프로젝트 코드 생성
- 생성된 프로젝트의 반복 개선
- 서비스 실행 상태 및 로그 확인
- 오류 분석 및 복구 요청

## 구조

- `back`: Python, FastAPI 기반 백엔드
- `front`: TypeScript, React 기반 프론트
- `pocket`: 생성된 서비스와 프로젝트별 실행 정보
- `compose.yaml`: Doraemon 백·프론트 Docker 실행 설정
- `.github/workflows/ci.yml`: 백·프론트 자동 검증

백엔드 구조는 아래와 같음

- `api`: FastAPI 라우터와 의존성 주입
- `schemas`: 요청·응답 및 영속 데이터 모델
- `services`: 프로젝트 생성, 실행, 개선 등의 애플리케이션 로직
- `repositories`: 파일 기반 프로젝트 데이터 저장
- `runtime`: 생성 프로젝트의 프로세스와 로그 관리
- `integrations`: LLM 공급자 연동
- `core`: 설정, 프로젝트 잠금 및 객체 조립

## 실행

Docker Desktop을 실행하고 `.env.example`을 `.env`로 복사

```powershell
Copy-Item .env.example .env
```

`.env`에 사용할 LLM의 API 키를 입력한 뒤 실행

```powershell
docker compose up --build
```

- 웹: http://localhost:3000
- API 문서: http://localhost:8000/docs
- 상태 확인: http://localhost:8000/api/health

종료:

```powershell
docker compose down
```

`pocket/`은 Docker 이미지에 포함되지 않고 로컬 폴더와 연결되어  
컨테이너를 종료하거나 다시 만들어도 생성된 프로젝트는 로컬에 유지됨

## 개발 의도 및 소감

완성된 서비스를 만드는 것뿐 아니라 에이전틱 AI가 실제 개발 과정에서  
어떤 방식으로 저장소를 확인하고 기능을 구현하는지 경험하는 것을 목적으로 진행함.

일반적인 생성형 AI 도구를 사용할 때보다 여러 파일과 구조를 함께 수정할 수 있어 편리했지만,  
AI가 만든 변경을 직접 확인하기 전까진 내가 프로젝트 구조를 제대로 이해하지 못한 상태가 되었음

반대로 생성된 결과물을 하나씩 확인하는 과정에서 FastAPI의 의존성 주입, 테스트 구성,  
CI와 Docker처럼 이전에 다뤄 보지 않았던 부분을 접하고 이해할 수 있었음.

현재 Docker 설정은 Doraemon 서비스 자체의 백엔드와 프론트를 실행하기 위한 범위이며,  
생성된 각 Doraemon 서비스를 별도 컨테이너로 실행하는 기능까지는 포함하지 않음
